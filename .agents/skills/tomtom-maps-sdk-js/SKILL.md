## Global conventions

- **Coordinates**: `[longitude, latitude]` — longitude first (GeoJSON order)
- **Place, route, range, geometry and traffic services return GeoJSON**: `Place = Feature<Point>`, `Places = FeatureCollection<Point>`; `reverseGeocode` and `getPlaceDetails` return one `Place`, `geometryData` polygons. **Not GeoJSON**: `getPOICategories`, `getPOICategoryCodes` and `getSearchSuggestions`
- **Map modules are async**: `await Module.create(map)` for data-owned modules (Places, Routing, Geometries, ReachableRanges, CustomGeoJSON, TrafficIncidentDetails, TrafficAreaAnalytics — a new independent instance per call), `await Module.get(map)` for style-owned ones (BaseMap, POIs, TrafficFlow, TrafficIncidents, Terrain, StylingFoundations — a shared controller)
- **`geocodeOne()` throws** if no result — use `geocode()` when uncertain
- **`discoverOnePlace()` throws** if no result — use `discoverPlaces()` when uncertain
- **Services work in Node.js** — no browser or map required
- **Map container CSS**: The map div AND `html, body` all need explicit height (`height: 100%` or `100vh`) and `margin: 0` — without this the map renders with zero height. Always include a complete HTML + CSS boilerplate in your answer, not just the TypeScript.
- **SDK first, MapLibre beneath**: `map.mapLibreMap` is the real MapLibre `Map`, so any MapLibre API, control or plugin works — but use the SDK feature wherever one exists: it survives `setStyle` and style upgrades, coordinates events, and follows the map's theme. Your own GeoJSON goes through `CustomGeoJSONModule` (`custom.md`), even for one layer; raw `addSource`/`addLayer` is for tile overlays. Which SDK feature replaces which raw call: `maplibre.md` § SDK first.
- **Layer placement**: MapLibre's `beforeId` inserts a raw layer **below** any style layer, but use the `mapStyleLayerIDs` anchors from `@tomtom-org/maps-sdk/map` — they are stable across styles; `CustomGeoJSONModule` takes their key names in `beforeLayerConfig`. Default **lines and polygons to `mapStyleLayerIDs.lowestLabel`** so all labels stay above them (the SDK's own default); points and markers go on top, with no anchor. Anchor table in `maplibre.md` (raw `addLayer`) and `custom.md` (`CustomGeoJSONModule` specs).
- **Provide visible UI feedback** for event handlers (toasts, panels, info bars) — not just `console.log`. Build real, functional UI that the user can see and interact with.

## Step 2: Confirm before integrating a preview feature

This step covers every SDK feature, whatever it is: a service, a map module, a utility, an agent
tool or a plugin. A feature is not generally available when:

- **Its doc says so**: a `Public preview` or `Private preview` callout at the top of the doc or of its
  section, or "public preview" or "private preview" beside a function, module, tool or plugin name.
- **It ships in a plugin below 1.0.0**: a `@tomtom-org/maps-sdk-plugin-*` package on a `0.x` version
  is in Public Preview even where its doc says nothing, and in Private Preview where its doc says so.
- **It is built on a preview feature**: an agent tool that calls a Private Preview service is in
  Private Preview too.

When the developer asks you to **integrate** such a feature into their application, so to write
or change code that uses it, stop before writing that code. Answering a question about it needs no
confirmation. When one request brings in several, such as the agent toolkit with the map-theme plugin
it depends on, name them all in one notice, each with its stage.

Show the developer this notice, filled in with the feature, its stage and that stage's terms
(`https://docs.tomtom.com/legal/public-preview` or `https://docs.tomtom.com/legal/private-preview`),
then ask whether to continue and wait for the answer:

> **`<feature>` is in `<Public | Private>` Preview** ([terms](<terms URL>)).
>
> - TomTom can change or withdraw it without the notice a generally available feature gets, so code
>   built on it may need changes in a later release.
> - *Private Preview only:* Freemium and Pay As You Grow API keys cannot use it. Your key needs access
>   from TomTom Sales, or the feature fails as its doc describes.
>
> Do you want to continue with it?

- **Yes**: go on to Step 3. Ask once per feature in a conversation.
- **No**, or no answer: leave that feature out. Carry on with the rest of the request, or stop if
  nothing is left.
